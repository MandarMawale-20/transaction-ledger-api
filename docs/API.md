# API reference

Base URL: `http://localhost:8000`. All bodies are JSON. Money values are strings with 2 decimals.
Interactive docs: `/docs`. Machine-readable spec: [`openapi.json`](openapi.json).
A no-build dashboard using these same endpoints is served at `/`.

## Error format

```json
{
  "error": {
    "code": "INSUFFICIENT_BALANCE",
    "message": "Account does not have sufficient balance.",
    "details": { "balance": "100.00", "requested": "150.00" }
  }
}
```

| HTTP | `code` | When |
|---|---|---|
| 404 | `ACCOUNT_NOT_FOUND` | well-formed id, no such account |
| 409 | `INSUFFICIENT_BALANCE` | debit or transfer exceeds the balance |
| 409 | `BALANCE_LIMIT_EXCEEDED` | a credit or transfer would push a balance above `9999999999999999.99` |
| 409 | `REFERENCE_ID_CONFLICT` | `reference_id` reused with a different payload |
| 422 | `INVALID_TRANSACTION_TYPE` | `type` is not `credit` / `debit` |
| 422 | `INVALID_AMOUNT` | amount missing, ≤ 0, > 2 decimals, > 16 integer digits, not a plain decimal (`1e2`, `1_000`, `+5`, `.5`), or a JSON number ≥ 10^13 (send a string) |
| 422 | `INVALID_PAGINATION` | `limit` outside 1–100 or `offset` < 0 or non-numeric |
| 422 | `VALIDATION_ERROR` | any other invalid request: bad JSON, missing/blank fields, unknown fields, malformed UUID, self-transfer |
| 404 | `NOT_FOUND` | unknown route |
| 405 | `METHOD_NOT_ALLOWED` | wrong HTTP method |
| 500 | `INTERNAL_ERROR` | unexpected server error |

Validation errors list each problem in `details.errors[]` as `{field, message, type}`.

## POST /accounts

```bash
curl -X POST localhost:8000/accounts -H 'Content-Type: application/json' \
  -d '{"name": "Asha Rao"}'
```

`201 Created`
```json
{ "id": "7231fc5c-2e1a-4c8b-9565-830045c6c1e9", "name": "Asha Rao",
  "balance": "0.00", "created_at": "2026-10-28T02:49:30.559806Z" }
```

Only `name` is accepted. Sending `balance`, `id` or any other field returns `422`.

## GET /accounts

Returns accounts, newest first.

| Query | Default | Rules |
|---|---|---|
| `limit` | 20 | 1–100 |
| `offset` | 0 | ≥ 0 |

```bash
curl "localhost:8000/accounts?limit=2&offset=0"
```

`200 OK`
```json
{ "items": [
    { "id": "7231fc5c-...", "name": "Asha Rao", "balance": "379.50", "created_at": "2026-10-28T02:49:30.559806Z" },
    { "id": "b18c0e42-...", "name": "Ben Ito",  "balance": "120.50", "created_at": "2026-10-28T02:51:11.120044Z" }
  ],
  "total": 2, "limit": 2, "offset": 0 }
```

`total` is the total number of accounts, not just this page. `offset` past the end returns an empty
`items` with the real `total`. Invalid `limit`/`offset` returns `422 INVALID_PAGINATION`.

## GET /accounts/{id}

Returns the account (same shape as above). `404` if it doesn't exist, `422` if the id isn't a UUID.

## GET /accounts/{id}/balance

`200 OK`
```json
{ "account_id": "7231fc5c-2e1a-4c8b-9565-830045c6c1e9", "balance": "379.50" }
```

## POST /accounts/{id}/transactions

`reference_id` is generated by the caller and acts as the idempotency key for the operation. Reuse the same
value when retrying the same logical request; do not generate a new one for a retry.

| Field | Type | Rules |
|---|---|---|
| `type` | string | `credit` or `debit` |
| `amount` | decimal | > 0, max 2 decimal places, max 16 integer digits. Send a **string** (`"10.50"`); JSON numbers work below 10^13 |
| `reference_id` | string | required, trimmed, 1–128 chars, unique per account |
| `description` | string | optional, max 500 chars |

```bash
curl -X POST localhost:8000/accounts/$ACC/transactions -H 'Content-Type: application/json' \
  -d '{"type":"credit","amount":"500.00","reference_id":"PAY-001","description":"Salary"}'
```

`201 Created`
```json
{ "id": "d79b5261-ff04-463d-b42b-9add6480c4c8", "account_id": "7231fc5c-...",
  "type": "credit", "amount": "500.00", "description": "Salary",
  "reference_id": "PAY-001", "transfer_id": null,
  "created_at": "2026-10-28T02:49:30.668508Z", "duplicate": false }
```

**Retry with the same body** → `200 OK`, the same transaction with `"duplicate": true`. Balance unchanged.

**Same `reference_id`, different type/amount/description** → `409 REFERENCE_ID_CONFLICT`.

**Debit larger than the balance** → `409 INSUFFICIENT_BALANCE`; nothing is stored.

**Credit that would exceed `9999999999999999.99`** → `409 BALANCE_LIMIT_EXCEEDED`; nothing is stored.

A retry of an earlier *successful* request always returns the original (`200`), even if the balance
has since fallen below the amount.

## GET /accounts/{id}/transactions

| Query | Default | Rules |
|---|---|---|
| `type` | both | `credit` or `debit` |
| `limit` | 20 | 1–100 |
| `offset` | 0 | ≥ 0 |

Newest first.

```bash
curl "localhost:8000/accounts/$ACC/transactions?type=debit&limit=10&offset=0"
```

`200 OK`
```json
{ "items": [ { "id": "...", "type": "debit", "amount": "120.50", "...": "..." } ],
  "total": 1, "limit": 10, "offset": 0 }
```

`total` is the number of rows matching the filter (not just this page).

## POST /transfers (bonus)

| Field | Type | Rules |
|---|---|---|
| `from_account_id` | uuid | must exist, differ from destination |
| `to_account_id` | uuid | must exist |
| `amount` | decimal | same rules as above |
| `reference_id` | string | required; unique per **source** account (B→A with the same reference is a separate transfer) |
| `description` | string | optional |

```bash
curl -X POST localhost:8000/transfers -H 'Content-Type: application/json' \
  -d '{"from_account_id":"'$A'","to_account_id":"'$B'","amount":"120.50","reference_id":"TRF-1","description":"Rent"}'
```

`201 Created`
```json
{ "id": "d2ee26d2-...", "from_account_id": "...", "to_account_id": "...",
  "amount": "120.50", "description": "Rent", "reference_id": "TRF-1",
  "created_at": "...",
  "transactions": [
    { "type": "debit",  "account_id": "<from>", "amount": "120.50", "transfer_id": "d2ee26d2-...", "...": "..." },
    { "type": "credit", "account_id": "<to>",   "amount": "120.50", "transfer_id": "d2ee26d2-...", "...": "..." }
  ],
  "duplicate": false }
```

The debit, the credit and both balance updates happen in one database transaction: either all
of it commits or none of it does. An identical retry returns `200` with `"duplicate": true`;
a retry with a different payload returns `409 REFERENCE_ID_CONFLICT`.
Errors: `404 ACCOUNT_NOT_FOUND` (either account; ids listed in `details.account_ids`), `409 INSUFFICIENT_BALANCE`, `409 BALANCE_LIMIT_EXCEEDED`, `422` (self-transfer, bad amount).

## GET /health

`200 {"status": "ok"}` once the database is reachable.
